PETRIC2 冠軍演算法（Speedy psv）：怎麼算、實測時間、怎麼改成硬體 list-mode online

2026-11-16｜資料：PETRIC2 測試集 NeuroLF_Esser2｜程式：SyneRBI/PETRIC2-Speedy（commit 3cb1173，main.py、rdp.py 一行未改）｜執行：本機 RTX 3070 Ti Laptop + STIR 6.5（CUDA 版）

重點
  • psv 是預條件 SVRG：每次只用 1/8 的資料算梯度，再用「上次算好的全部梯度」修正誤差；步長乘上一個依影像和 RDP 決定的逐 voxel 預條件 P。
  • 本機實跑：讀檔 2.1 s，setup 26.5 s，第 98 次更新（12.25 epoch）到達門檻，比賽計時 153 s（官方 A100 排行榜約 78–87 s）。
  • 時間分布：likelihood 子集梯度佔 76%（前投影＋CPU 逐 bin 運算＋反投影），子集 sensitivity 佔 15%，RDP、預條件、影像更新合計不到 5%。
  • 子集梯度裡，GPU 只做投影；CPU 對 663 萬個 bin（95% 是 0）做加法、正規化、比值佔 41%。改成 list-mode 後只需要處理 260 萬個事件，而且全部在板上做。
  • 估計：list-mode 版 psv 到門檻需要約 18.4 epoch 的投影量，DE10-Pro v10（8 lanes）約 12 s，32-lane slab 約 4.4 s；本機 GPU 事件式寫法約 6.8 s。要贏 GPU 需要 ≥16 lanes 或 online 提前算，詳見第 6–8 節。

1. 比賽給什麼資料、要算什麼

PETRIC2 每個資料集給的都是已經 histogram 好的 sinogram，不是 list-mode：

檔案意義Esser2 大小
prompts.sy：每個 bin 的計數（2304 sinograms × 128 views × 180 bins = 5308 萬個 bin，只有 250 萬個 > 0）212 MB
mult_factors.sm：每個 bin 的偵測效率 × 衰減212 MB
additive_term.sa：散射＋隨機（除以 m 之前）212 MB
OSEM_image.hvOSEM 影像（主辦方免費給的初始值）10 MB
kappa.hv、penalisation_factor.txtRDP 的空間權重 κ 和強度 β10 MB
PETRIC/*.hv參考影像和評分用的 VOI（參賽程式看不到）—

影像 95 × 163 × 163 voxels（1.66 mm）。前向模型和目標函數：

ŷ = m · (A x + a)                                  （A：parallelproj Joseph 投影）
Φ(x) = Σ_i [ y_i log ŷ_i − ŷ_i ]  −  β · R(x)        （最大化；x ≥ 0）
R(x) = ½ Σ_j Σ_{k∈26鄰居} w_jk κ_j κ_k (x_j − x_k)² / (x_j + x_k + γ|x_j − x_k| + ε)     （RDP，γ = 2）
∇Φ(x) = Aᵀ( m·y/ŷ ) − Aᵀm − β ∇R(x)

門檻（PETRIC2 wiki）：全物體 RMSE ≤ 1%、背景 RMSE ≤ 1%、每個 VOI 平均值誤差 ≤ 0.5%（都除以參考影像背景平均），而且要連續 10 次評分都維持。計時從讀完資料開始，所以 list-mode → sinogram、散射和隨機估計、OSEM 初始影像都不計時。

2. psv 演算法流程

每一步做什麼、程式在哪裡

步驟計算主要運算程式
② 初始影像OSEM 做 6 mm 高斯濾波3 次 1D 卷積（stencil）main.py __init__：pre_filter.process(OSEM_image)
③ 子集 sensitivitys_k = c·Aₖᵀ mₖ，k = 1…8反投影（所有 bin，含 y = 0）partitioner.data_partition → get_subset_sensitivity
④ 預條件P = x / (Σs_k + 2·diagH·x)，diagH 用 26 鄰居公式高斯濾波＋26 鄰居 stencil（GPU，cupy）calc_precond、rdp.py _diag_hessian
⑥⑦ likelihood 梯度∇L_k = c·Aₖᵀ( m·y/ŷ ) − s_k，ŷ = m(c·Aₖx + a)前投影 → 逐 bin 比值 → 反投影SIRF/STIR gradient()
⑥⑦ RDP 梯度β/M · ∇R(x)26 鄰居 stencil（STIR CUDA）_subset_prior_fct.gradient
⑧ 影像更新x + α·P·d，再取 max(0, ·)逐 voxelupdate()

為什麼這樣設計：SVRG 讓子集梯度的變異數隨收斂變小，所以步長不用一直縮小；P 讓不同 voxel 的步長配合它的 Poisson 曲率（x/Aᵀ1，也就是 EM 的步長）和 RDP 曲率，兩者取調和平均。這是 PETRIC1 冠軍 MaGeZ ALG1 的作法，PETRIC2 前三名都是它的變形。

3. 簡單例子：2 個 voxel、4 條 LOR、2 個子集

用跟 main.py 一樣的公式手算（toy.py）。為了讓小例子收斂，步長用 0.8 而不是 3.5，c = 1。

LORA（voxel 1, voxel 2）may子集
1(1.0, 0.0)0.90.24子集 0
2(0.5, 0.5)0.80.22子集 1
3(0.0, 1.0)1.00.21子集 0
4(0.8, 0.2)0.70.23子集 1

RDP：β = 0.5、ε = 0.01、γ = 2；初始 x₀ = (2, 1)。

  1. sensitivity：s = Aᵀm = (0.9 + 0.4 + 0.56, 0.4 + 1.0 + 0.14) = (1.86, 1.54)。
  2. 前投影：子集 0 的 ŷ = m(Ax + a) = (0.9·2.2, 1.0·1.2) = (1.98, 1.20)；子集 1 的 ŷ = (0.8·1.7, 0.7·2.0) = (1.36, 1.40)。
  3. 比值＋反投影：子集 0 的 ∇L₀ = Aᵀ(m·y/ŷ) − Aᵀm = (0.918, −0.167)；子集 1 的 ∇L₁ = (0.828, 0.348)。
  4. RDP 梯度：∇R(x₀) = (0.140, −0.180)；每個子集分到 1/M：g₀ = ∇L₀ − ∇R/2 = (0.848, −0.077)，g₁ = (0.758, 0.438)，存成梯度表。
  5. 預條件：diagH = (0.032, 0.128)，P = x / (s + 2·diagH·x) = 2/(1.86 + 0.128), 1/(1.54 + 0.256) = (1.006, 0.557)。
  6. 第 0 次更新（全梯度）：d = g₀ + g₁ = (1.607, 0.361)，x₁ = x₀ + 0.8·P·d = (3.293, 1.161)。
  7. 第 1 次更新（只算子集 1）：在 x₁ 算新的 g₁ = (0.157, 0.175)，d = 2·(新 g₁ − 舊 g₁) + g_sum = 2·((0.157, 0.175) − (0.758, 0.438)) + (1.607, 0.361) = (0.405, −0.165)，x₂ = (3.615, 1.088)。這次只用了一半的 LOR，方向卻接近全梯度。
  8. 繼續：(3.688, 1.238) → (3.951, 1.100) → (3.921, 1.097) → (3.913, 1.095) → … 收斂到 MAP 解 (3.911, 1.096)。

真實資料一模一樣，只是 x 有 252 萬個 voxel，每個子集有 663 萬個 bin，A 由 parallelproj 即時算（不存矩陣）。

4. 實際執行：讀資料 → 計算 → 結果

怎麼跑的：psv 需要 SIRF，Windows 沒有 SIRF。SIRF 的 PET 部分只是包裝 STIR，所以我寫了一層很薄的 SIRF/CIL 相容介面（shim/），底下直接呼叫本機 STIR 6.5（CUDA 版，parallelproj 投影、CudaRelativeDifferencePrior），讓隊伍的 main.py、rdp.py 不改一行執行。評分公式照抄 petric.py。驗證：STIR 算出的 sensitivity 和我們 EXP-S6 的 parallelproj 模型比值中位數 1.0000、第 99 百分位 1.0001（少數 FOV 邊緣 voxel 在 STIR 是 0，因為 STIR 會截成圓柱 FOV）。和 SIRF 的差別見第 9 節。

6. 哪裡可以硬體化

psv 的步驟現在的問題硬體化的做法現有基礎
list-mode → sinogram（不計時）要先收完、排好不做：事件直接進 FPGAEXP-S6 事件格式（32 B/事件）
③ 子集 sensitivity（15%）dense 反投影 5308 萬 bin改依時間切子集後 s_k = s/M，只算一次；s 只和掃描儀、衰減有關，掃描期間就能先算反投影引擎
前投影（30%）dense 投影全部 bin，再拷回 host事件式前投影，只算 260 萬事件（每事件平均 143 個 Joseph sample），結果留在片上v10 8 lanes 1106 M sample/s；slab 模型 32 lanes 3.1 G/s
CPU 逐 bin 比值（31%＋4%）663 萬 bin/子集，95% 是 0每個事件緊接前投影做 w = m/(m(c·fwd + a))：1 次乘加＋1 次除法的逐點單元；零 bin 不存在需新增（很小）
反投影（10.5%）GPU 要 atomicbank 配置＋無衝突排序，事件 w 直接累加EXP-S3/S4 已在板上驗證
RDP 梯度、對角 Hessian、高斯濾波（2%）不是瓶頸3×3×3 串流 stencil（line buffer）需新增
SVRG 梯度表、x、P（1%）每次更新讀寫幾張影像放 DDR：Esser2 每張 10 MB，8＋4 張 = 121 MB；每次更新讀 g_k、g_sum、P、x，寫 x（約 50 MB）DE10-Pro DDR4

計算：每 epoch 3.73 億次前投影 sample ×2（前＋反）= 7.46 億；只算投影，不含 stencil、DDR 讀寫和 setup。GPU 事件式數字是 EXP-S7 在本機量的，A100 會更快。

結論：只把 psv 搬上 FPGA，8 lanes 會輸給寫得好的 GPU（12 s 對 7 s），但能量少約 5 倍。要在時間上贏，需要：(1) 16–32 lanes（slab 架構）；或 (2) 利用 list-mode online，在收資料期間就先算，讓「最後一個事件之後的延遲」變短。第 (2) 點 GPU 很難做到，因為 GPU 版需要先 histogram 成 sinogram。

7. 改成 list-mode online 要改什麼

要改的地方psv 原版list-mode online 版
資料sinogram（y, m, a 每個 bin）事件（LOR 端點或晶體對、m、a、時間），計數為 0 的 bin 不出現
子集依 view 切（16 views 一組）依時間 / 事件編號切；新到的一批事件就是一個新子集
sensitivity每個子集各算一次全部 s 一次算好（掃描前或掃描中），時間子集用 s·(該批事件佔比)
likelihood 梯度Aᵀ(m·y/ŷ) − s_kΣ_事件 Aₑᵀ(mₑ/ŷₑ) − s_k，每個事件 y = 1
SVRG 全梯度每 2 epoch 掃全部資料資料還在增加時「全部」沒有定義 → 需要新設計（見下）
初始影像主辦方給的 OSEM（免費）收資料期間自己算（online 階段的產出）

三個候選做法（要用實驗決定）

  1. A：online LM-OSEM 暖機 → 收完後 list-mode psv。收資料時每來一批事件做一次 LM-OSEM 子迭代（代替比賽給的 OSEM），事件存進 DDR；收完後跑 list-mode psv。最簡單，psv 部分完全照原版。
  2. B：online SVRG（成長中的資料）。每來一批新事件，把它當成新子集：算它的梯度並加進梯度表和 g_sum（等於把全梯度「增量更新」），其他時間照 SVRG 輪流更新舊子集。收完時梯度表已經是完整的，直接進入原版 psv。需要驗證：梯度表混了不同時間點的 x，是否仍收斂。
  3. C：LM-SPDDY（Speedy pd2 改成 list-mode）。每個事件一個對偶變數，天生 online；排行榜慢約 1.5–1.8 倍，但每 epoch 只掃 1 次資料，片上記憶體可能放得下對偶變數（Esser2 10 MB）。

評比要報兩個數字：(1) 和比賽相同定義的時間；(2) 最後一個事件進來後，到達門檻的延遲。GPU 那邊的 (2) 要加上 histogram、傳輸、OSEM。

8. 交給 PET 研究 session 的工作

  1. 在本機 GPU 實作 list-mode psv（時間切子集），用 D:\PET_DATA\listmode\NeuroLF_Esser2 的事件和本報告的評分方式，確認仍能在約 12 epoch 到達門檻。
  2. 實作做法 A 和 B（必要時 C），量「最後一個事件之後的延遲」。
  3. 把選定演算法的逐點單元（w = m/ŷ、SVRG 組合、x 更新）、RDP stencil 和 DDR 梯度表加到 slab 事件投影引擎，在 DE10-Pro 上合成（先 8 lanes、64×64×32 小影像驗證，再放大），記錄 Fmax、資源、功耗。
  4. 判斷能不能贏：同一份 Esser2 資料，比較 FPGA 和 GPU（psv 原版和 GPU 事件式兩種）的 (1)、(2) 時間和能量。

9. 限制

  • 不是 SIRF。SIRF 用 ProjDataInfoSubsetByView 把資料實際切成 8 份，各自只投影自己的 view；STIR Python 沒有提供這個類別，所以我用 STIR 內建子集。parallelproj 因此每次前投影都算全部 view（0.32 s，照 SIRF 做法約 0.04–0.07 s）。照 SIRF 做法估計子集梯度約 0.52 s，到門檻約 100 s，和 A100 排行榜 78–87 s 相近。前投影的佔比被高估了，CPU 逐 bin 運算的佔比被低估了。
  • setup 的 sensitivity 時間在三次執行分別是 57、28、24 s（第一次包含磁碟快取），表中用最後一次。
  • 全物體 RMSE 在最後兩個軸向平面和參考影像不一致（第 4 節），門檻判斷去掉了這兩個平面。
  • CPU 逐 bin 那一項是「子集梯度總時間減去前投影、取出、反投影」得到的，不是直接量的。
  • GPU 同時有其他程式在用（約 20–50%），GPU 時間有波動。FPGA 時間是用實測吞吐量估計的，尚未在板上跑完整演算法。
